Use it in your project#

Say that your project uses Date Versioning (rule 1) and link to this page. A README badge does both:

DateVerYY.MM.DD

[![DateVer](https://img.shields.io/badge/DateVer-YY.MM.DD-{{accent_hex}})](https://datevers.ing)

Replace YY.MM.DD with your current version in its canonical form (Shields writes a hyphen as --, so 26.10.01-1 becomes 26.10.01--1). Keep a changelog too: a Date Version says when, and the changelog says what.

Using Date Versioning with AI tools and programs#

You can point any AI assistant or program at https://datevers.ing/spec.md (or /llms.txt) and tell it the project uses Date Versioning. Both are plain text, so there is nothing to scrape. Paste this into your assistant's instructions, your AGENTS.md or CLAUDE.md, or a prompt:

This project uses Date Versioning (https://datevers.ing/spec.md): versions are the UTC release date as YY.MM.DD, with -1, -2… for further releases the same day.

For programs there is a small descriptor with the regular expressions, the time zone and the SemVer-form rules: /datever.json. The specification also has a permanent page and Markdown file for each version, for example /spec/{{spec_version}}/ and /spec/{{spec_version}}.md.
